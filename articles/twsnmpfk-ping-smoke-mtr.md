# はじめに

オープンソースの軽量ネットワーク統合監視ツール **[TWSNMP FK](https://github.com/twsnmp/twsnmpfk)** の **v2.3.0** において、ネットワーク診断の基本である **PING機能の大幅な強化** が行われました。

日頃のネットワーク運用・トラブルシューティングにおいて、単発のPing（死活確認）だけでは以下のような問題の切り分けが難しいケースが多くあります。

* 「Pingは通るが、Web会議の音声や映像が途切れる（ジッターや瞬間的なパケットロスが発生している）」
* 「通信が遅い原因が、社内LANなのか、ISP回線なのか、途中のルーターなのか特定できない」
* 「時間帯によって通信品質がどのようにゆらいでいるのかをグラフィカルに把握したい」

こうした課題を解決するため、TWSNMP FK v2.3.0 では新たに **「Smoke (Smokeping)」** と **「MTR (My Traceroute)」** の2大機能が搭載され、さらに測定結果をワンクリックで診断・アドバイスしてくれる **「AI解説」** や、恒常的な監視に使える **「Smokepingポーリング」** が追加されました。

本記事では、これら新機能の詳細と具体的な活用方法をご紹介します。

---

# PING画面の刷新と4つの動作モード

TWSNMP FK のマップ画面やノードリストから対象ノードを選択し、PINGダイアログを開くと、上部にモード切り替えボタンが配置されています。

![](/images/twsnmpfk-ping-smoke-mtr/map_ping.png)
*▲ 刷新されたPING画面。上部のボタンから直感的にモードを切り替え可能*

選択できる動作モードは以下の4種類です。

| モード | 概要 | 主な用途 |
| --- | --- | --- |
| **通常 Ping** | 標準的なICMP Echo Requestを送信 | 単発・連続の死活確認、応答時間の時系列推移の確認 |
| **Smoke** | 200ms間隔の高頻度バースト送信で遅延のゆらぎとロスを測定 | ジッター（ゆらぎ）の可視化、微小なパケットロスの検出 |
| **トレースルート** | TTLを1から順に増やして経路を探索 | 宛先までの経由ルーター（ホップ）の一覧取得 |
| **MTR** | 経路上の全ホップを検知し、各ホップへ継続サンプリング | 経路全体のボトルネック特定、ホップ別遅延・ロスのリアルタイム追跡 |

測定期間は **「1分間」「3分間」「5分間」「10分間」「無制限（連続）」** から選択でき、パケットサイズ（64〜1500バイト）やTTLの指定、応答成否を音で知らせる **BEEP機能** も備わっています。

# Smoke機能：ジッターとパケットロスの濃淡可視化

## Smokepingとは？

ネットワーク品質を測る上で、平均応答時間だけでなく **「遅延のばらつき（ジッター）」** や **「わずかなパケットロス」** を把握することは極めて重要です。これを可視化する手法として広く知られているのが **Smokeping** です。

TWSNMP FK の **Smokeモード** では、200ms間隔で連続パケットを高速送信し、得られた結果を一定間隔（タイムウィンドウ）ごとに集計して **Smokepingチャート** を描画します。

![](/images/twsnmpfk-ping-smoke-mtr/map_ping_smokeping.png)
*▲ Smokepingチャート。応答時間の中央値、最小〜最大の範囲（煙）、パケットロス率が一目でわかる*

## チャートの読み方

* **中央値（緑の折れ線グラフ）**:
  外れ値（突発的な遅延）の影響を受けにくい、安定した応答時間の中央値（Median RTT）を示します。
* **Smoke（水色の帯状エリア）**:
  その時間帯における最小応答時間（Min）から最大応答時間（Max）までの幅（ジッター）を表現しています。帯が狭いほど通信が安定しており、帯が上下に広がっている時間帯は遅延の揺らぎ（Jitter）が大きいことを意味します。
* **パケットロス率（下部の縦棒グラフ）**:
  パケットロス率に応じてバーの色が変化します（正常時は薄緑、軽微なロスはオレンジ、多量のロスは赤）。

:::message
**活用シーン**
「動画配信がカクつく」「リモートデスクトップのレスポンスが瞬間的に引っかかる」といった突発的・断続的な品質低下を調査する際、Smokeモードを数分間実行するだけで、どのタイミングでジッターやロスが発生しているかが明瞭に浮かび上がります。
:::

# MTR (My Traceroute) 機能：ホップ別リアルタイム経路診断

## MTRとは？

従来の `traceroute` は経路上の各ルーターを1〜3回程度調べるだけですが、**MTR (My Traceroute)** は経路上のすべてのホップ（中継ルーター）を特定した上で、各ホップに対して **継続的にPingサンプリング** を行います。

これにより、「経路のどの地点から遅延が跳ね上がっているのか」「どのルーターでパケットロスが発生しているのか」をリアルタイムに診断できます。

![](/images/twsnmpfk-ping-smoke-mtr/map_ping_mtr.png)
*▲ MTR画面。ホップフロー図、詳細統計テーブル、プロファイルチャートを統合表示*

## MTR画面の構成要素

TWSNMP FK の MTR 画面は、トラブルの原因箇所を直感的に見つけられるように設計されています。

### 1. ホップフローマップ（トポロジー表示）
画面上部に、送信元から宛先端末までのホップ順がフロー図として表示されます。途中のルーターのIPアドレスや位置情報（GeoIP）が視覚的に把握できます。

### 2. MTR統計テーブル
各ホップについての詳細なメトリクスがリアルタイムに集計・更新されます。

* **Hop / Host**: TTL番号と中継ルーターのIPアドレス
* **Snt**: 送信パケット数
* **Loss%**: パケットロス率
* **Last / Avg / Best / Wrst**: 最新・平均・最小・最大の応答時間（ミリ秒）
* **StDev**: 応答時間の標準偏差（値が大きいほど遅延が不安定）
* **ボトルネック表示**: 遅延急増地点や高ロス率ホップの警告表示

### 3. MTRプロファイルチャート
横軸にホップ、縦軸に応答時間（最小・平均・最大レンジ）およびロス率をグラフ化し、経路全体のレイテンシの段差をひと目で確認できます。

:::message
**トラブルシューティングのポイント**
あるホップ以降のすべてのルーターで一律にロス率や遅延が上昇している場合、その手前の区間（回線や機器）にボトルネックが存在することが一発で判明します。
:::

# AI（LLM）によるPING・MTRの自動診断・解説

TWSNMP FK の特徴である **AI（LLM）連携機能** が、PING画面にも統合されました。画面右下の **`[AI解説]`** ボタンをクリックするだけで、現在測定中のデータ（Ping/Smoke/MTR）をAIが自動分析します。

![](/images/twsnmpfk-ping-smoke-mtr/map_ping_mtr_ai.png)
*▲ MTRの測定結果をAIが解説。ボトルネックの場所や推奨される切り分け手順をアドバイス*

## AIが分析・提示してくれる内容

* **ネットワーク品質の総合評価**:
  平均レイテンシ、ジッター、ロス率から通信品質を総合評価。
* **ボトルネック・障害箇所の特定**:
  MTRデータから「どのホップで遅延が急増しているか」「ローカルLAN内か、WAN/ISP境界か、相手先クラウドか」を自動判定。
* **想定される原因と推奨アクション**:
  MTU不一致、Wi-Fi電波干渉、帯域枯渇、ルーターのICMPレートリミットなど、考えられる技術的要因と確認手順を日本語で解説。

OpenAIやGeminiなどのクラウドLLMだけでなく、**OllamaなどのローカルLLM（オフライン運用）** にも完全対応しています。

# 継続的な監視：Smokepingポーリング機能

単発の診断ツールとしてだけでなく、日々の定常監視（ポーリング）にも Smokeping の仕組みが利用できるようになりました。

ノードのポーリング設定で **`種別: PING`**、**`モード: smoke`** を選択することで、定期的に短周期連続Pingを実行し、統計情報に基づいた閾値判定を行えます。

## パラメータと判定スクリプト

* **パラメータ例**: `count=10,size=64,ttl=64`
  * `count`: 1回のポーリングで送信する連続パケット数（例: 10回）
  * `size`: 送信サイズ（バイト）
  * `ttl`: TTL
* **利用可能なJavaScript判定変数**:
  * `avg` / `rtt` / `mean`: 平均応答時間（ナノ秒）
  * `min` / `max`: 最小・最大応答時間（ナノ秒）
  * `median`: 中央値応答時間（ナノ秒）
  * `jitter`: ジッター（`max - min`、ナノ秒）
  * `loss`: パケットロス率（%、`0.0` 〜 `100.0`）
  * `fail` / `lossCount`: ロスしたパケット数
  * `count`: 送信パケット総数

### スクリプトの例

```javascript
// パケットロス率が10%未満、かつ平均応答時間が100ms未満なら正常
loss < 10.0 && avg < 100 * 1000 * 1000
```

```javascript
// ジッター（遅延のゆらぎ）が50msを超えたらアラート
jitter < 50 * 1000 * 1000
```

ポーリングテンプレートやAIポーリング作成アシストにも対応しているため、自然言語で「パケットロスが5%以上またはジッターが大きい場合にアラート」と入力するだけで設定を自動生成することも可能です。

# おわりに

TWSNMP FK v2.3.0 で追加された **Smoke** と **MTR** により、ネットワークの死活確認にとどまらず、**「品質のゆらぎ」** や **「経路ボトルネックの精密な特定」** がデスクトップアプリから手軽に実行できるようになりました。

さらにAI解説やSmokepingポーリングと組み合わせることで、原因究明のスピードアップやプロアクティブな障害検知が実現します。
