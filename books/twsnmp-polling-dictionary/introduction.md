# ポーリング設定の基本

TWSNMP FC および TWSNMP FK における、ポーリング設定の基本的な操作と画面の入力項目について解説します。

## 1. ポーリング設定画面の開き方

ポーリングの設定は、各ノードの「ポーリングリスト」画面から行います。

- **新規追加**: ポーリングリスト画面の上部にある `<追加>` ボタンをクリックすると、新しいポーリングを作成するための設定画面が開きます。
- **既存の編集**: リストに表示されている既存のポーリング行にある `<編集>` ボタン（またはアクションメニューから編集を選択）をクリックすると、そのポーリングの設定内容を編集できます。

## 2. ポーリング設定画面の入力項目

ポーリング設定画面には、主に以下の入力項目があります。（※選択した「種別」によって表示される項目が一部異なります）

- **名前 (Name)**
  - ポーリングの識別名です。リスト上で分かりやすい名前を入力します。（例: `PING死活監視`, `CPU使用率`）
- **種別 (Type)**
  - ポーリングの種類を選択します（`ping`, `snmp`, `http`, `stun`, `syslog`, `email` など）。この選択によって、後続の入力フィールドや動作が切り替わります。
- **モード (Mode)**
  - 種別の中での詳細な動作モードを指定します。（例: PINGでの `smoke`、Syslogでの `sigma`、SNMPでの `traffic` や `sysUpTime` など）
- **パラメータ (Params)**
  - モードの実行に必要な追加情報を指定します。指定フォーマットは種別やモードによって異なります（例: OIDやポート番号、STUNサーバー、Smokeping設定 `count=10,size=64` など）。
- **フィルター (Filter)**
  - 取得した結果から特定の文字列や条件に合致するものだけを抽出（または除外）するための正規表現を指定します（Sigmaモードでは適用するルールパック名等を指定）。
- **抽出 (Extractor)**
  - 主にHTTPやコマンド実行などで、複雑な応答データ（JSONやHTMLなど）から特定の値を抜き出すための条件（JSONPathやGrokパターンなど）を指定します。
- **スクリプト (Script)**
  - 取得したデータを基に、正常か異常かを判定するためのJavaScriptロジックを記述します。最終的に `true` なら正常、`false` なら設定した「障害レベル」の状態になります。
- **障害レベル (Level)**
  - ポーリング（スクリプトでの判定）が失敗した際に、ノードをどの状態にするか（`high`: 重度, `low`: 軽度, `warn`: 警告など）を指定します。
- **ログモード (Log Mode)**
  - ポーリングの実行結果をどのようにログに記録するかを指定します：
    - `保存しない`: 結果ログをDBに保持しません。
    - `常に保存`: 毎回のポーリング結果を記録します。
    - `状態変化時のみ保存`: 正常から障害、あるいは障害から復帰した時のみ記録します。
    - `異常検知`: 収集した数値を機械学習・統計アルゴリズムで解析し、普段と異なる挙動（外れ値）を自動検知します。
- **異常検知モード (Anomaly Algorithm)** ※ログモードが「異常検知」時のみ表示
  - 以下の8種類の高度なアルゴリズムから選択できます：
    1. **Isolation Forest**: 孤立木により外れ値を高速に検知（推奨・デフォルト）
    2. **ホテリング理論 (Hotelling's T2)**: 単変量・正規分布に基づく統計的異常検知
    3. **k近傍法 (k-NN)**: 近傍データ点との距離に基づく外れ値検知
    4. **マハラノビス距離**: 複数変数の共分散を考慮した多変量外れ値検知
    5. **基本統計 (Z-Score)**: 平均値と標準偏差からの乖離度合による検知
    6. **局所外れ値因子法 (LOF)**: データ密度の粗密に基づく局所的異常検知
    7. **オートエンコーダー (Autoencoder)**: ニューラルネットワークの再構成誤差を用いた検知
    8. **LSTM**: 時系列の遷移順序や連続性の破綻を捉えるリカレントモデル
- **ベクトル化する変数名** ※ログモードが「異常検知」時のみ表示
  - 異常検知の対象とする数値変数の名前（カンマ区切りで複数指定可能）。
- **MQTTサーバーURL / トピック / 送信するデータ名**
  - ポーリングで取得した測定値を外部のMQTTブローカーにリアルタイムパブリッシュして他システムと連携するための設定です。
- **説明 (Description)**
  - このポーリングの目的や運用上のメモを自由に記述できる備忘録フィールドです。

## 3. AIアシストによるポーリング自動生成

TWSNMP FK（v2.4.0〜）では、ポーリング編集ダイアログに **`[AIアシスト]` ボタン** が新設されました（内蔵AI `tensai` または外部LLMと連携）。

![AIアシストポーリング作成](/images/books/twsnmpfk-manual/ai_polling_assist.png)

1. ポーリング追加画面で `[AIアシスト]` ボタンをクリックします。
2. 「監視したい内容」を自然言語で入力します。
   - 例: `Webサーバーの応答時間が3秒を超えたら警告にしたい`
   - 例: `パケットロスが5%を超えたら検知するSmokeping監視を作成して`
   - 例: `STUNサーバーを使ってグローバルIPの変化を監視したい`
3. AIが対象ノードの情報（IPアドレス、対応プロトコル、OS種別等）を考慮し、**最適な種別、モード、パラメータ、JavaScript判定スクリプト** を自動的に推論・生成して各フィールドへ自動入力してくれます。
