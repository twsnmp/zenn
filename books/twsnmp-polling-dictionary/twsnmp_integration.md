# TWSNMP 統合監視

別の拠点で動作している TWSNMP 本体の状態を監視し、複数の監視拠点を統合管理します。

## 1. 概要
リモート（別拠点）の TWSNMP が提供する REST API (`/api/status`) にアクセスし、その「健康状態（マップの合計状態）」と「収容ノード・ポーリング数」を取得します。
大規模な多拠点監視において、各監視サーバー自体が正常に動作しているかを確認する「監視の監視」として機能します。

## 2. ポーリング設定
- **種別**: `twsnmp`
- **モード**: (空欄)
- **パラメータ**: (通常は空欄。接続先URLはノード設定に依存します)
- **スクリプト**: リモート側のマップ状態に基づく判定。

## 3. 取得結果 (PE.Result)

- **`status`**: リモートTWSNMPの全体状態 (`normal`, `warn`, `high`, `low` 等)。
- **`nodeCount`**: リモート側で管理されている全ノード数。
- **`pollingCount`**: リモート側で実行されている全ポーリング数。
- **`rtt`**: APIレスポンス時間（ナノ秒）。

## 4. JavaScript 判定例

### リモート拠点が「正常」であることを監視
- **スクリプト**: `status == "normal"`

## 5. 注意点
- **APIキーの設定**: 接続には、リモート側で許可された管理者権限、またはAPIアクセス権限が必要です。ノード設定の「URL」にAPIトークンを含めるか、共通設定であらかじめ認証情報を定義しておく必要があります。
- **ネットワーク経路**: 監視元からリモート監視サーバーのWebポート（通常 8080 や 443）へのTCP疎通が必要です。
- **再帰監視の防止**: 監視サーバー A が B を監視し、B が A を監視するような構成は、状態変化のループ（バウンス）を避けるため慎重に設計してください。
