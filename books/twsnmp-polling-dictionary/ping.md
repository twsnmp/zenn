# PING

PINGポーリングは、ICMP（Internet Control Message Protocol）のエコー要求パケットを監視対象に送信し、その応答を確認するネットワーク管理の最も基本的な手法です。TWSNMPでは、用途に合わせて3種類のPINGポーリングを利用できます。

## 1. 普通のPING
最も標準的なPING監視です。

- **動作**: 監視対象にICMP Echoパケットを送信し、折り返しの応答を確認します。
- **データサイズ**: デフォルトで64バイト（データ部分）固定です。
- **取得可能なデータ**:
  - `rtt` (応答時間): パケットが往復するのにかかった時間。
  - `ttl` (Time To Live): 受信したパケットのTTL値（v1.20.0以降）。
- **設定方法**:
  - 種別: `PING`
  - パラメータ: 空欄
- **主な用途**: サーバーやネットワーク機器の死活監視。

## 2. パラメータを指定したPING
特定のネットワーク環境（低速回線やMTUの制限がある環境など）の調査に利用します。

- **動作**: データサイズや送信時のTTLを任意に指定して実行します。
- **設定方法**:
  - パラメータ欄に `key=value` 形式で指定します（カンマ区切りで複数指定可）。
  - 例: `size=1472,ttl=64`
- **指定可能なキー**:
  - `size`: データパケットのサイズ（0 〜 2999バイト）。
  - `ttl`: 送信パケットのTTL値（1 〜 255）。
- **ヒント**: パラメータに数値のみ（例: `1200`）を記入した場合は、自動的に `size` として扱われます。

## 3. 回線速度診断 (Line Condition Mode)
回線の帯域幅や安定性を詳細に調査するための高度なモードです。

- **動作**: 
  - サイズの異なる2種類のPING（64バイトと1364バイト）を交互に送信します。
  - その応答時間の差分から、回線の「伝送速度（スループット）」と「伝搬遅延（物理的な距離による遅延）」を推定します。
  - 正確な統計を得るため、最大20回の試行を行い、有効なデータを5回取得するまで測定を継続します（最低3回の成功が必要）。
- **取得可能なデータ**:
  - `fail`: 5回の有効データ取得までに失敗した回数。
  - `rtt` (伝搬遅延): 回線自体の遅延（パケットサイズに依存しない遅延）の平均値。
  - `rtt_cv` (遅延変動係数): 遅延のばらつき。値が小さいほど安定しています。
  - `speed` (回線速度): 推定された回線速度 (Mbps)。
  - `speed_cv` (速度変動係数): 速度のばらつき。
  - `ttl`: 受信パケットのTTL値。
- **設定方法**:
  - **モード**: `line` を指定。
  - 注意: v1.19.0以前ではパラメータ欄に `line` と入力する必要がありましたが、現在はモード欄で指定可能です。
- **主な用途**: 暗号化VPN越えの通信品質調査、モバイル回線の安定性確認など。

## 4. Smokepingモード (Smoke Mode)
回線の品質劣化や遅延の揺らぎ（ジッター）、微細なパケットロスを高精度に測定するための高度なモードです（v2.3.0〜）。

- **動作**: 
  - 監視対象に対して、指定された回数（デフォルト10回）のICMPパケットを約200ミリ秒間隔で連続送信します。
  - 受信した応答データから、最小・最大・平均・中央値の応答時間、ジッター（揺らぎ）、パケットロス率を算出します。
- **設定方法**:
  - **モード**: `smoke` を指定。
  - **パラメータ**: `key=value` 形式で指定（カンマ区切り、省略可）。
    - `count`: 連続送信するパケット数（1 〜 100、省略時は `10`）。
    - `size`: 送信データサイズ（0 〜 2999バイト、省略時は `64`）。
    - `ttl`: 送信パケットのTTL値（1 〜 255）。
    - 例: `count=10,size=64`
- **取得可能なデータ (PE.Result / スクリプト変数)**:
  - `rtt` / `avg` / `mean`: 平均応答時間（ナノ秒）。
  - `min`: 最小応答時間（ナノ秒）。
  - `max`: 最大応答時間（ナノ秒）。
  - `median`: 中央値応答時間（ナノ秒）。
  - `jitter`: ジッター（`max - min` の遅延差、ナノ秒）。
  - `loss`: パケットロス率（パーセント、`0.0` 〜 `100.0`）。
  - `fail` / `lossCount`: ロスしたパケットの個数。
  - `count`: 送信した総パケット数。
  - `ttl`: 最後に受信したパケットのTTL値。
- **JavaScript 判定例**:
  - パケットロス率10%未満かつ平均応答時間100ms未満で正常:
    `loss < 10.0 && avg < 100 * 1000 * 1000`
  - 遅延の揺らぎ（ジッター）が50ms以内であることを監視:
    `jitter < 50 * 1000 * 1000`
- **主な用途**: VoIPやWeb会議などのリアルタイム通信回線の品質監視、拠点間VPNやクラウド接続回線の微細な障害・品質劣化検知。

## 設定テンプレート例
```json
[
  {
    "Name": "PING監視",
    "Type": "ping",
    "Level": "low",
    "Descr": "標準的なPING死活監視",
    "AutoMode": ""
  },
  {
    "Name": "Smokeping監視",
    "Type": "ping",
    "Mode": "smoke",
    "Params": "count=10,size=64",
    "Script": "loss < 10.0 && avg < 100 * 1000 * 1000",
    "Level": "low",
    "Descr": "PINGを連続送信(count)して応答時間(min, max, avg, median, jitter)やパケットロス率(loss %)を測定するSmokepingモード監視。"
  },
  {
    "Name": "パラメータ指定PING",
    "Type": "ping",
    "Params": "size=1300,ttl=128",
    "Level": "low",
    "Descr": "サイズ1300バイト、TTL128で実施",
    "AutoMode": "disable"
  },
  {
    "Name": "回線速度診断",
    "Type": "ping",
    "Mode": "line",
    "Level": "low",
    "Descr": "回線品質（速度・遅延）を詳細に測定",
    "AutoMode": "disable"
  }
]
```
