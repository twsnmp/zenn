# NetFlow (IPFIX) 監視

ネットワークフローデータを解析し、通信帯域や接続パターンを監視します。

## 1. 概要
ルーターやスイッチから送信される NetFlow (v5/v9) や IPFIX データを収集・解析します。
SNMPでは把握しきれない「誰が誰と、どのようなプロトコルで通信しているか」を定量的に監視できます。

## 2. ポーリング設定
- **種別**: `netflow` (または `ipfix`)
- **モード**:
    - `traffic`: 特定の通信パターン（ホスト間やポート）のトラフィック量を計算します。
    - `count`: 指定した期間内のフロー発生件数を数えます。
    - `stats`: フロー全体の統計（ユニークIP数、不自然な通信 `fumbles` など）を監視します。
    - `check`: 各フローの詳細内容を判定します。
- **フィルター**: 通信を絞り込む条件。
- **スクリプト**: 判定ロジック。

## 3. 取得結果 (PE.Result)

### `traffic` モード時
- **`bps`**: 条件に合致する通信の平均ビットレート。 (単位: bit/s)
- **`pps`**: 条件に合致する通信の平均パケットレート。 (単位: pkt/s)
- **`bytes`**: 指定期間内の総転送量。 (単位: bytes)
- **`packets`**: 指定期間内の総パケット数。 (単位: packets)

### `stats` モード時
- **`IPs`**: 出現した個別IPアドレスの数。
- **`flows`**: ユニークな接続ペア数。
- **`fumbles`**: 異常な通信の疑い（TCPのSYNのみ、ICMPエラーなど）のカウント。

## 4. JavaScript 判定例

### 特定サーバーのHTTPSトラフィック過多を検知
- **モード**: `traffic`
- **フィルタ**: `ip=10.0.0.5,port=443`
- **スクリプト**: `bps < 10000000` (10Mbpsを超えたら通知)

## 5. 注意点
- **コレクター設定**: システム設定で NetFlow コレクターを有効にし、対象機器から TWSNMP サーバーの UDP ポート（通常 2055 や 4739）へデータを送信するように設定する必要があります。
- **Fumblesの定義**: TWSNMPでは、パケット数が4未満のTCPフローや、特定のICMPエラーメッセージを「不自然な通信 (Fumbles)」として分類しています。
