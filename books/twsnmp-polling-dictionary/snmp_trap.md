# SNMP トラップ監視

対象機器から送信されるSNMPトラップ（通知）を受信して、異常を検知・記録します。

## 1. 概要
SNMPエージェントが自発的に送信するイベントメッセージ（トラップ）を待ち受け、その内容に基づいてアラートを生成します。
特定のエラー発生、リンクのアップ/ダウン、構成の変更などをリアルタイムに近い形で把握できます。

## 2. ポーリング設定
- **種別**: `trap`
- **モード**:
    - `check`: 受信したトラップの内容を一つずつGrokや正規表現で判定します。
    - `count`: 指定した期間内に条件に一致するトラップがいくつ届いたかを調べます。
    - `stats`: トラップ全体の統計量（種類数や送信元数など）を調べます。
- **パラメータ**: 送信元ホストのフィルタ（通常は空欄。機器を特定したい場合はIPなどを指定）。
- **フィルター**: トラップ内容（Enterprise OIDや変数内容）を絞り込む正規表現。
- **抽出 (Extractor)**: 内容を解析するためのGrokパターン名。
- **スクリプト**: 判定式。

## 3. 取得結果 (PE.Result)

### `check` モード
Grokによる抽出結果や、トラップの全データが表示されます。
また、JavaScript内で以下のグローバルな値が利用可能です：
- `Enterprise`: トラップの送信元OID。
- `GenericTrap`: 一般トラップ型（0〜6）。
- `SpecificTrap`: 固有トラップ番号。
- `Variables`: バリアブルバインディングの内容文字列。

### `count` モード
- **`count`**: 指定期間内の合致トラップ数。

## 4. JavaScript 判定例

### 特定の固有トラップ（例：101）の発生を検知
- **モード**: `check`
- **スクリプト**: `SpecificTrap == 101`

### トラップ内の特定の文字列による判定
- **モード**: `check`
- **フィルタ**: `.*Error.*`
- **スクリプト**: `true` (フィルタに一致すれば即アラートとする場合)

## 5. 注意点
- **ポート開放**: TWSNMPサーバー側で UDP 162番ポートが開放され、トラップを受信可能な状態である必要があります（システム設定でトラップ受信を有効にする必要があります）。
- **統計モードの活用**: 短時間に大量のトラップが発生する「トラップバースト」対策には、必ず `stats` モードや `count` モードを併用して判定しきい値を設けてください。
