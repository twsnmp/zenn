# DNS サーバー監視

DNSサーバーの応答性および、ドメイン名の解決結果が正しいかを監視します。

## 1. 概要
指定したDNS名（ドメイン、ホスト、IP）に対して、各種リソースレコードの問い合わせを行います。
IPアドレスの予期しない変更の検知（ダイナミックDNS監視など）や、重要なメールサーバーのMXレコード、構成情報のTXTレコードなどが正しく引けるかを確認できます。

## 2. ポーリング設定
- **種別**: `dns`
- **モード**:
    - `ipaddr`: ホスト名からIPアドレスを解決します（前回と変化があれば異常と判断）。
    - `addr`: IPアドレスから逆引きを試行します。
    - `host`: `LookupHost` を使用して解決します。
    - `mx`: MXレコード（メールサーバー）を問い合わせます。
    - `ns`: ネームサーバーレコードを問い合わせます。
    - `txt`: TXTレコードを問い合わせます。
    - `cname`: CNAMEレコードを問い合わせます。
- **パラメータ**: 問い合わせの対象（例: `www.google.co.jp`, `8.8.8.8`）。
- **スクリプト**: 取得結果の個数（`count`）や内容による詳細判定。

## 3. 取得結果 (PE.Result)

- **`rtt`**: 問い合わせ完了までの時間（ナノ秒）。
- **`count`**: 取得されたレコードの数。
- **`[モード名]`**: 取得された具体的データ（カンマ区切り、または `ipaddr` モード時は単一文字列）。

## 4. JavaScript 判定例

### 特定のリレー先MXレコードが登録されているか
- **モード**: `mx`
- **パラメータ**: `example.com`
- **スクリプト**: `mx.indexOf("aspmx.l.google.com") != -1`

### 解決結果が1つ以上あることを確認
- **スクリプト**: `count > 0`

### 特定のIPアドレスであることを確認
- **モード**: `ipaddr`
- **スクリプト**: `ip == "192.168.1.50"`

## 5. 注意点
- **ipaddrモードの特殊挙動**: このモードでは `pe.Result["ip"]` に前回の値を保持しており、解決された最新のIPと異なると、スクリプトなしでもポーリングレベルに応じた異常状態（再起動検知と同様のUI表現）になります。
- **タイムアウト**: DNSクエリはタイムアウトが発生しやすいため、状況に応じてリトライ回数を調整してください。
