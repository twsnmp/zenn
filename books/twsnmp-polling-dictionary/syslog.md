# Syslog 監視

## 異常検知ログ・PRI監視

Syslogのプライオリティの統計監視および、機械学習を活用した異常検知機能について解説します。

### 1. 概要
Syslogに含まれる **PRI (Priority)** 値には、ファシリティとセベリティの情報が含まれています。TWSNMPではこれらを統計的に分析することで、普段とは異なるログの発生パターンを自動的に検知します。
また、特定のポーリングについては、ログデータを異常検知エンジン（twsnmpfk/twsnmpfc内部のロジック）に送り、特異なログを抽出できます。

### 2. ポーリング設定
- **種別**: `syslog`
- **モード**: `pri`
- **フィルター**: 監視対象のログを絞り込む正規表現。
- **スクリプト**: 統計量（特定のセベリティの件数など）を用いた判定。

### 3. 取得結果 (PE.Result)
- **`count`**: 指定期間内の総受信数。
- **`pri_0`**: Emergency (緊急) の件数。
- **`pri_1`**: Alert (警報) の件数。
- **`pri_2`**: Critical (致命的) の件数。
- **`pri_3`**: Error (エラー) の件数。
- **`pri_4`**: Warning (警告) の件数。
- **`pri_5`**: Notice (通知) の件数。
- **`pri_6`**: Informational (情報) の件数。
- **`pri_7`**: Debug (デバッグ) の件数。

## Syslog レポート機能

Syslogメッセージから特定の情報（ユーザー、デバイス、通信フロー）を自動的に抽出し、TWSNMP内部のレポートシステムへ登録します。

### 1. 概要
ログの内容を監視するだけでなく、ログの中に含まれる活動記録を解析して「誰がログインしたか」「新しい端末が接続されたか」といった動的な台帳（レポート）を作成します。
これにより、セキュリティ監査や構成管理を自動化できます。

### 2. ポーリング設定
- **種別**: `syslog`
- **モード**:
    - `user`: ログイン・ログアウト活動を抽出します。
    - `device`: IPアドレスとMACアドレスの対応関係を抽出します。
    - `flow`: FWやルーターのログから通信フロー情報を抽出します。
- **パラメータ**: 通常、送信元ホスト名のフィルタを指定します。
- **抽出 (Extractor)**: 各情報を抽出するための Grok パターン名（必須）。
- **スクリプト**: 成功率などの統計量で判定したい場合に記述します。

## Sigma脅威検知・コンプライアンス監査 (Sigma Mode)

受信したSyslogストリームに対して、オープンソースの標準脅威検知ルール [SIGMA](https://sigmahq.io/) エンジンを実行し、サイバー攻撃や不正侵入、セキュリティ監査違反をリアルタイムに検知する高度なモードです（v2.4.0〜）。

### 1. 概要
TWSNMP FKには、Linux認証（SSH/Sudo等）、Windowsイベント、ネットワーク脅威、Webアクセスログ用など **11種類・合計75ルールの厳選ルールパック** がバイナリに標準組み込みされています。外部のルールファイルを配置することなく、Syslogポーリングで `sigma` モードを選択するだけで即座に脅威検知を開始できます。

短時間での連続認証失敗などを判定するスライディングウィンドウ相関検知にも対応しています。

### 2. ポーリング設定
- **種別**: `syslog`
- **モード**: `sigma`
- **パラメータ**: 監視対象ホスト名（空欄時は全ホストのSyslogを対象）。
- **フィルター**: 適用するルールパック名（例: `linux-auth,network-threats`）や個別ルール名を指定（省略時は全有効ルールが適用されます）。
- **抽出 (Extractor)**: ルール評価前にログ行を絞り込むための正規表現（オプション）。
- **スクリプト**:
  - **空欄時（デフォルト動作）**:
    検知された脅威の最大深刻度（Critical/High/Medium/Low）に応じて、自動的にポーリングの障害状態に遷移します。
  - **記述時**:
    検知数や深刻度別の変数を用いて柔軟なしきい値判定を記述できます。

### 3. 取得結果 (PE.Result / スクリプト変数)
- **`count`**: マッチしたSigmaルールの総検知数。
- **`hitLogs`**: ルールに合致したログメッセージの行数。
- **`scanned`**: スキャン対象となった総ログ行数。
- **`critical`**: 深刻度 Critical の脅威検知件数。
- **`high`**: 深刻度 High の脅威検知件数。
- **`medium`**: 深刻度 Medium の検知件数。
- **`low`**: 深刻度 Low の検知件数。
- **`info`**: 深刻度 Informational の検知件数。
- **`compliance`**: MITRE ATT&CK や PCI-DSS / CIS などのコンプライアンス規格タグに合致した検知件数。
- **`lastRule`**: 最後に検知したSigmaルールのタイトル名。

### 4. JavaScript 判定例

#### Critical または High の重大な脅威のみをアラート対象にする
- **スクリプト**: `critical == 0 && high == 0`
- 低深刻度（Low/Info）の検知を除外し、即座に対応が必要なインシデントのみを検知します。

#### いずれかの脅威検知またはコンプライアンス違反があればアラート
- **スクリプト**: `count == 0 && compliance == 0`
