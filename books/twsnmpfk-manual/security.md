## アドレスリスト

ネットワーク内で検出されたIPアドレス、MACアドレス、ベンダー情報、ドメイン情報を一覧管理します。

![](/images/twsnmpfk/2023-11-28_05-28-14.png)

- **STUN グローバルIP確認**:
  画面上部の `[STUN]` ボタンをクリックすると、STUNサーバーを利用して自環境の外部グローバルIPアドレス、外側ポート番号、逆引きホスト名、送信元ローカルアドレス、RTT、GeoIP位置情報を即座に取得・確認できます。
- **アドレス管理のAI解説**:
  画面下の `[AI解説]` ボタンをクリックすると、正常アドレスの要約に加え、IP重複、APIPA (169.254.x.x)、IPアドレス変更、MACアドレス変更などの異常エントリを個別に精査し、運用上のリスクや想定原因、推奨対策をAI（LLM）が詳しく診断・提示します。

![](/images/twsnmpfk/address_stun.png)

### 分析レポート

- **IP使用状況 (IPAM) 階層化ドリルダウン (v2.5.0)**:
  ネットワーク内のアドレス空間を効率的に分析・把握するためのIPAMレポートが刷新されました。
  - **サブネット相対利用密度ヒートマップ**: 全アドレス範囲を100分割で正規化集約し、大規模・広域ネットワークでも軽量・高速に全体の利用状況を俯瞰表示します。
  - **階層化ドリルダウン表示**: 広域アドレス空間では /24 サブネットブロック単位で集約表示され、ブロックをクリックすることで各ブロック内（1〜254）の個別ホスト割当状況へシームレスにドリルダウンできます。
  - **サブネット範囲一覧テーブル**: 登録されたアドレス範囲の開始/終了IP、アドレス数、使用数、利用率を一覧表示し、クリックで選択中の詳細表示を切り替えられます。
  - **ホストリアルタイム検索**: ホスト名、IPアドレス、MACアドレスによるインライン検索に対応し、一致するアドレスを即座にハイライト表示します。

![](/images/twsnmpfk/address_list_ip.png)

- **力学・円形モデル**: IPとMACの紐づけを視覚化し、重複やなりすましを検知。

![](/images/twsnmpfk/2023-11-28_05-38-57.png)

## サーバー証明書の監視

SSL/TLSサーバー証明書の有効期限や発行者を一覧管理し、期限切れ前に通知することが可能です。

![](/images/twsnmpfk/cert_list.png)

- **証明書管理のAI解説**:
  `[AI解説]` ボタンをクリックすると、監視対象の証明書の有効期限、運用状態、セキュリティリスク、更新・再発行手順についてAIからアドバイスを受けられます。

## PKI CA (認証局) 構築・サーバー機能 (v2.5.0)

TWSNMP FKは独自のプライベート認証局（CA）を内蔵し、証明書の発行・管理だけでなく、業界標準の自動証明書管理プロトコルサーバー（ACME, EST, SCEP, OCSP, CRL）をオールインワンで運用できます。

![](/images/twsnmpfk/2025-03-09_16-25-47.png)

- **CSR作成**: 証明書署名要求を生成。
- **証明書一覧**: 発行済み証明書の管理と失効処理。

### サーバー制御画面とプロトコル設定 (v2.5.0)

サーバー制御ダイアログから、各種証明書発行・配信サーバーの起動とパラメータを一括管理できます。

![](/images/twsnmpfk/pki_3.png)

| 項目 | 内容 |
| --- | --- |
| **ACME/ESTサーバー** | ACME（自動証明書管理環境）および EST（RFC 7030）サーバー機能を起動します。 |
| **CRL/OCSP/SCEPサーバー** | 証明書失効リスト（CRL）、OCSP、および SCEP サーバー機能を起動します。 |
| **ACMEサーバーの基本URL** | ACMEおよびESTが応答するベースURLを指定します。 |
| **CRLの更新間隔** | 失効リストの更新間隔（時間単位）。 |
| **証明書の期間** | 発行する証明書の有効期間（時間単位）。 |

### EST (RFC 7030 / Enrollment over Secure Transport) サーバー

ACMEサーバーを有効にすると、同一のHTTPSポート上でRFC 7030準拠のESTサービスが自動的に提供されます。

- **対応エンドポイント（標準および任意ラベルに対応）**:
  - `GET /.well-known/est/cacerts`（または `GET /.well-known/est/:label/cacerts`）: Root CA証明書を含むPKCS#7 (`certs-only`) をBase64形式で取得。
  - `POST /.well-known/est/simpleenroll`（または `POST /.well-known/est/:label/simpleenroll`）: PKCS#10 CSRを受け取り、認証およびノード照合後に署名済み証明書を返却。
  - `POST /.well-known/est/simplereenroll`（または `POST /.well-known/est/:label/simplereenroll`）: 既存証明書の更新。
- **mTLS および HTTP Basic認証による厳格なセキュリティ**:
  - **mTLS（クライアント証明書認証）**: 当CAから発行された有効かつ未失効のクライアント証明書によるTLS接続を自動認証。
  - **HTTP Basic認証**: クライアント証明書がない場合、CSRが対応する対象ノードのパスワード（`node.Password`）およびユーザー名（`node.User` が設定されている場合）によるHTTP Basic認証を必須とし、不正な証明書発行を防止します。
- **ノード照合**:
  - CSR内のSAN（DNS名、IPアドレス、RFC 4043 PermanentIdentifier）、Subject CN、またはアクセス元IPがマップ登録ノードと一致するか厳格に検証されます。

### ACMEサーバーの検証方式拡充と端末構成証明（Device Attestation）

ACMEサーバーは、マップ上に登録されたノードと照合しながら、多様な検証方式で安全に証明書を発行します。

- **DNS識別子 (`dns`)**: `http-01`, `tls-alpn-01` に加え、ワイルドカード証明書（`*.example.com`）の **`dns-01`** チャレンジ検証およびノード照合に対応。
- **IPアドレス識別子 (`ip` / RFC 8738)**: IPv4 / IPv6 アドレスに対する `http-01` および `tls-alpn-01`（`.in-addr.arpa.` / `.ip6.arpa.`）検証に対応。
- **端末構成証明 (`permanent-identifier` / `hardware-module`, `device-attest-01`)**:
  - **Apple Managed Device Attestation**（`apple`、iOS 16 / iPadOS 16 / macOS 14以降）および **YubiKey PIV / Smallstep**（`step`）の端末構成証明に対応。
  - 発行証明書のSAN拡張に RFC 4043 `PermanentIdentifier`（OID `1.3.6.1.5.5.7.8.3`）を記録し、ノードのシリアル番号やUDIDと確実に紐付けます。
  - **ノード登録方法**: 対象ノードの「名前」「説明」「公開鍵」「メモ」のいずれかにデバイスのシリアル番号またはUDIDを記載しておくことで自動的に照合されます。
